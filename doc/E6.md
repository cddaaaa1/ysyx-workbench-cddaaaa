# E6 简易运行时环境 —— 测试与命令清单

> 参考：[E6 简易运行时环境 | 官方文档](https://ysyx.oscc.cc/docs/2607/e/6.html)

本章核心目标：让 NPC 能**批量、自动地运行用 AM 编译出来的程序**，并逐步补上 UART（字符输出）和时钟（计时），最后用 `archbench` 做性能评测。

> 以下命令都假设在工作区根目录下（目录里已含 `am-kernels`、`abstract-machine`、`riscv-tests`、`archbench`、`fceux-am`）。

## 1. 体验 AM：红白机游戏

验证 AM 能编译/运行，检查画面、按键、声音。

```sh
cd fceux-am
make ARCH=native run
```

## 2. 运行第一个编译的程序（dummy）

先验证 RISC-V 工具链，再编译到 minirv，最后让 NPC 读入并执行 `dummy`（在 `halt()` 处死循环）。

需要先改代码：

- PC 复位值 → `0x80000000`
- `pmem_read`/`pmem_write` 按距 `0x80000000` 的偏移访问
- 存储器数组改成 128MB

```sh
cd am-kernels/tests/cpu-tests
make ARCH=riscv32-nemu ALL=dummy     # 验证工具链，生成 dummy-riscv32-nemu.{bin,elf,txt}
ls build/
make clean
make ARCH=minirv-npc ALL=dummy       # 生成 dummy-minirv-npc.{bin,elf,txt}
ls build/
```

## 3. 搭建批量运行流程

需要改代码：

- `abstract-machine/am/src/riscv/npc/trm.c` 的 `halt()` 加 `ebreak`，并 `mv a0, %0; ebreak`
- 仿真环境识别 `ebreak` 后按 `a0` 输出 `HIT GOOD TRAP` / `HIT BAD TRAP`，并把结果从 `main()` 返回
- `abstract-machine/scripts/platform/npc.mk` 加 `run` 规则（可用 `$(IMAGE).bin`）

```sh
cd am-kernels/tests/cpu-tests
make ARCH=minirv-npc ALL=dummy run   # 期望 HIT GOOD TRAP
make ARCH=minirv-npc ALL=wrong run   # 期望 HIT BAD TRAP（修复返回码后应为 FAIL）
make ARCH=native     ALL=wrong run   # 对照：native 上也是 FAIL
```

## 4. 运行更多程序

### riscv-tests（批量自动运行，验证指令正确性）

```sh
bash init.sh riscv-tests
cd riscv-tests
make ARCH=minirv-npc run TEST_ISA=i  # 全部 RV32I
make ARCH=minirv-npc run ALL=addi    # 只跑 addi
```

### cpu-tests（需要先放好 klib，并建议加 DiffTest 机制）

```sh
# 下载 klib-minirv-npc.tar.bz2，解压出 klib-minirv-npc.a 放到 abstract-machine/klib/build/
cd abstract-machine/klib/build
touch klib-minirv-npc.a              # 更新 mtime，避免 make 认为过时
cd ../../../am-kernels/tests/cpu-tests
make ARCH=minirv-npc run             # 全部测试
make ARCH=minirv-npc run ALL=fib     # 只跑 fib
```

## 5. UART 字符输出

需要改代码：

- `abstract-machine/am/src/riscv/npc/trm.c` 实现 `putch()`
- 仿真环境加 UART 行为模型（地址 `0x10000000` 写 → `fputc`）

```sh
cd am-kernels/kernels/hello
make ARCH=native run                 # 先看预期输出
make ARCH=minirv-npc run
```

### benchmark（先把 dhrystone/coremark 迭代次数改成 2 轮）

```sh
cd ../../benchmarks/dhrystone
make ARCH=minirv-npc run
cd ../coremark
make ARCH=minirv-npc run
cd ../microbench
make ARCH=minirv-npc run mainargs=test
```

## 6. LLaMa 大模型

```sh
bash init.sh archbench
cd archbench/bench/202.llama2
make ARCH=native run mainargs=test    # 先看预期（test 规模输出 "Once"）
make ARCH=minirv-npc run mainargs=test
```

### UART 状态寄存器 + 并行跑全部 archbench

需要改代码：仿真环境加状态寄存器（`0x10000004` 随机就绪），`putch()` 查询就绪后再输出。

```sh
cd archbench/scripts
bash run.sh ARCH=minirv-npc mainargs=test
```

## 7. 时钟（计时）

需要改代码：

- 仿真环境加时钟行为模型（`0x20000000` 低 32 位 / `0x20000004` 高 32 位）
- 实现 `abstract-machine/am/src/riscv/npc/timer.c` 的 `__am_timer_uptime()`

```sh
cd am-kernels/tests/am-tests
make ARCH=minirv-npc run mainargs=t   # 每 1 秒输出一句话
```

然后重新跑 benchmark，此时会输出有意义的时间/分数。

## 8. 红白机游戏（字符模式）

注释掉 `fceux-am/src/config.h` 里的 `#define HAS_GUI`，在 NPC 上跑（作为功能测试即可）。

## 9. 性能评测

先跑 `train` 规模，看分数和几何平均：

```sh
cd archbench/scripts
bash run.sh ARCH=minirv-npc mainargs=train
```

再改 `get_time()`：用「已仿真周期数 ÷ 频率」换算微秒，分别按 100MHz、1000MHz、以及 ECC 综合报告里的真实频率重跑对比。

## 10. ECC 综合评估频率

先用流水灯跑通 ECC，再综合 NPC（把 DPI-C 访存移到 NPC 外部，用 `` `ifndef SYNTHESIS `` 包住不可综合代码）。

```sh
cd ecc
./ecc init light
# 改 ecc/light/ecc.toml 里的 PDK 路径，preset 设为 syn_sta
./ecc run --project light
# 结果看 light/runs/default/Synthesis_yosys/report/post_synthesis/qor_summary.rpt
```

---

**小提醒**：

- PC 复位必须改到 `0x80000000`
- `cpu-tests` 依赖的 `klib-minirv-npc.a` 要放到 `abstract-machine/klib/build/` 并 `touch`
- `archbench` 脚本需要 `time`、`parallel`、`python3-numpy`
