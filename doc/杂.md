
### github ssh 连接

1. 定位网络问题：HTTPS 走代理可以访问，直连失败；SSH 直连 22、443 端口也超时，因此让 SSH 通过已有的 HTTP 代理连接。
2. 修复目录问题：发现 WSL 的 ~/.ssh 被误建为空文件，将其备份后重新创建目录。
3. 复用 Windows 密钥：将已经登记到 GitHub 的 Windows 私钥复制到 WSL，并设置权限，成功认证为 cddaaaa1。
4. 保存 SSH 配置：在 ~/.ssh/config 中指定代理、密钥和 GitHub SSH 的 443 端口，让普通 Git SSH 命令自动使用这些设置。
5. 验证仓库访问：通过 git ls-remote 确认 Spike 仓库已经能够访问。
